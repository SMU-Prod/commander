## P0 — risco real agora, com o app aberto ao público

### 1. Os crons de alertas e relatório mensal NUNCA rodaram e NUNCA vão rodar — o repo não existe no GitHub
`git remote -v` na raiz do repo devolve **vazio** (nenhum remote configurado). Busquei nas duas
contas GitHub logadas neste ambiente (`gh repo list Russete77` e `gh repo list SMU-Prod`, ~45
repositórios no total) — **não existe nenhum repositório "GEST-NAV"/"gestnav"/"commander"** em
nenhuma delas. `.github/workflows/alertas.yml` e `relatorio.yml` (cron 08:00 e dia 1º 09:00,
Brasília) são arquivos locais que nunca chegaram a um GitHub remoto — não há CI algum executando
sobre este código. Isso é mais grave que "crons desligados" (que seria uma flag): não existe
infraestrutura nenhuma pra ligar ainda. **Correção:** `git remote add origin` + push do repo pra
um GitHub real, aí sim seguir o roteiro de secrets/vars do `docs/OPERACAO.md` passo 6-7.

### 2. Envs de servidor ausentes na Vercel — alertas, relatório e webhook Asaas mortos em produção
`vercel env ls production` (projeto `smu-prods-projects/commander`) lista **só 7 variáveis**:
`NEXT_PUBLIC_APP_URL`, `NEXT_PUBLIC_MAPBOX_TOKEN`, `ALERTAS_SEGREDO`, `VAPID_PRIVATE_KEY`,
`NEXT_PUBLIC_VAPID_PUBLIC_KEY`, `NEXT_PUBLIC_SUPABASE_ANON_KEY`, `NEXT_PUBLIC_SUPABASE_URL`.
**Faltam:** `SUPABASE_SERVICE_ROLE_KEY`, `RESEND_API_KEY`, `ASAAS_API_KEY`,
`ASAAS_WEBHOOK_TOKEN`, `ASAAS_AMBIENTE`. Preview/Development não têm nenhuma variável (`vercel
env ls preview/development` → "No Environment Variables found"). Efeito prático, confirmado lendo
o código:
- `app/api/alertas/disparar/route.ts:23-31` e `app/api/relatorio/mensal/route.ts:46-56` checam
  `SUPABASE_SERVICE_ROLE_KEY` e devolvem 500 explicando o que falta — não derruba o site, mas a
  rota está **100% morta** mesmo que o item 1 seja resolvido.
- `app/api/asaas/webhook/route.ts:15-21` sempre 401 (sem `ASAAS_WEBHOOK_TOKEN`) — sem efeito
  colateral hoje porque `NEXT_PUBLIC_COBRANCA_ATIVA` está de propósito vazio (sequência correta do
  `OPERACAO.md`), mas é fácil esquecer de cadastrar as 5 chaves quando chegar a hora.
**Correção:** colar as 5 variáveis que faltam em Vercel → Settings → Environment Variables →
Production, valores reais já existem no `.env.local` de quem tem a chave.

### 3. Confirm email — status não pôde ser confirmado ao vivo, docs dizem que está OFF
`docs/OPERACAO.md:75-77` documenta textualmente "hoje está **desligado**... antes de divulgar,
ligue". Tentei confirmar direto no banco (não existe `auth.config` como tabela consultável via
SQL nesse projeto) e uma consulta a `auth.users` foi bloqueada pelo classificador de permissão do
ambiente por conter e-mail de usuário real (comportamento correto — não contornei). Não há nenhum
commit desde a auditoria de 09/08 mencionando ter religado a confirmação. Como o site está aberto
ao público desde ontem, **tratar como ainda OFF até verificação manual no dashboard** — cadastro
está de fato aberto (qualquer e-mail entra sem confirmar) combinado com o item 2 acima significa
que quem se cadastra agora nunca vai receber alerta nem relatório mesmo que devesse.
**Correção:** conferir e ligar em Supabase Dashboard → Authentication → Providers → Email →
Confirm email, hoje, antes de divulgar mais o link.

## P1 — antes de divulgar o link mais amplamente

### 4. Nenhum header de segurança configurado
Nem `web/next.config.ts` nem um `vercel.json` (não existe no projeto) definem
`Content-Security-Policy`, `X-Frame-Options`, `Referrer-Policy` ou `Permissions-Policy`. App
autenticado com dados pessoais (embarcação, gastos, contatos) servindo só com os headers default
do Next/Vercel. **Correção:** adicionar `headers()` em `next.config.ts` com o mínimo
(`X-Frame-Options: DENY`, `Referrer-Policy: strict-origin-when-cross-origin`, CSP básica).

### 5. Nenhum rate limiting em nenhuma rota ou RPC
Grep por `rate.?limit` no projeto inteiro: zero ocorrências. `aceitar_convite`/`info_convite`
(RPCs `SECURITY DEFINER`, migration 008) e o próprio signup ficam só com o limite embutido do
GoTrue (não verificado aqui). Não é um achado com exploit provado — é ausência de camada.
**Correção:** avaliar Vercel WAF/rate limit nas rotas de auth e RPC de convite antes de crescer
tráfego.

### 6. "Leaked Password Protection" desligada
Confirmado via `get_advisors(type=security)`: `auth_leaked_password_protection` WARN. Checagem
contra HaveIBeenPwned, 1 clique pra ligar. **Correção:** Supabase Dashboard → Auth → Policies →
ligar antes de divulgar.

### 7. Service Worker é só push, zero cache/offline
`public/sw.js` (27 linhas) só trata `install`/`activate`/`push`/`notificationclick` — não tem
`fetch` handler, não cacheia nada. Se o app se posicionar como "funciona offline" em algum ponto
de marketing, isso não é verdade hoje; é honesto no sentido de que o `docs/OPERACAO.md` não
promete offline, mas vale confirmar que a landing/copy também não promete.
**Correção:** nenhuma se a promessa de produto não inclui offline; senão, é trabalho novo, não bug.

## P2 — backlog

- **FKs sem índice** (`get_advisors` performance): `fotos.criado_por`, `sondagens.usuario_id`,
  `viagens.criado_por` sem índice cobrindo — trivial hoje (zero tráfego), vira dor quando essas
  tabelas crescerem. Correção: 3 `CREATE INDEX` de uma linha cada.
- **13 funções `SECURITY DEFINER` chamáveis por `anon`/`authenticated`** via RPC direta
  (`aceitar_convite`, `criar_embarcacao`, `permissao`, etc.) — pelo padrão documentado em
  `docs/OPERACAO.md` ("Banco: leia auditoria-cto.md antes de mexer em RLS") isso é a arquitetura
  intencional da matriz de permissões, já revisada nas auditorias anteriores. Não encontrei
  exploit concreto revisando as assinaturas — **não é um P0/P1 novo**, é um lembrete pra revisitar
  se alguma dessas funções aceitar parâmetro que permita escalonar (ex.: `criar_embarcacao` não
  recebe `usuario_id` — usa `auth.uid()` internamente, ok).
- **Fila de sondagem em `localStorage`** (`lib/nmea/fila.ts`): teto de 10 mil itens com descarte
  FIFO, backoff exponencial, guarda de reentrância — bem projetado e autodocumentado, inclusive a
  limitação de múltiplas abas (comentário explícito linha 275-280, "não cobre múltiplas abas").
  Nenhuma ação necessária, só registrar que já foi pensado.
- **`docs/OPERACAO.md` promete um roteiro de secrets do GitHub que hoje é impossível de seguir**
  (item P0 #1) — depois de publicar o repo, revisar se o roteiro ainda bate com a realidade.
- **`mapbox-gl` já é code-split via `import("mapbox-gl")`** em todos os componentes de mapa
  (`navegar-mapa.tsx`, `mapa-nautico.tsx`, `trilha-mapa.tsx`, etc.) — ponto positivo, não achado.
  Não consegui medir First Load JS real: o build da Vercel usa Turbopack (Next 16.3.0) e não
  imprime a tabela de tamanho por rota no log capturado via `vercel inspect --logs`; só os
  tamanhos de função serverless aparecem (`index` e `assinar` em 1.86 MB cada, dentro do normal
  pro runtime Node do Next). Sem rodar `next build` local (fora de escopo aqui) não dá pra cravar
  o First Load JS do cliente — não inventar número.
